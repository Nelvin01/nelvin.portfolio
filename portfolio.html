AI Automation

Receiving Digitizer with AI Auto-Fill

Paperwork that came with received shipments (packing slips, BOLs, invoices, damage reports) was kept on paper, which made it slow to find later and easy to lose.

What I built: a phone-first web app. A receiver scans a QR code at the receiving door, photographs the paperwork, checks it's readable, and submits. Scans go to private cloud storage, the details go to a database, and a searchable archive lets the team find any document in seconds. Sign-in is role-based through Auth0.

The AI layer: in V2, Claude reads the captured pages and fills in the form fields automatically, flagging anything it couldn't read clearly. The receiver only types what's missing. If the AI is slow or unavailable, the app falls back to manual entry so receiving never stops.

How I shipped it safely: V2 runs as a separate preview deploy against clearly named test tables and storage, so new features get tested without touching live data.

Paper → searchable Every received document captured, stored, and findable from a phone
📄

Claude Code Claude API (vision) Supabase Netlify Functions Auth0 JavaScript GitHub
Dashboards

Live Production Tracking Dashboards

Production status lived in Airtable reports that were hard to read on the floor, and some were too big for Airtable to even display.

What I built: a suite of 69 live web dashboards covering every stage of production: cutting, sewing, foam, blowing, packing, inventory pulls, shipments between locations, custom orders, overdue and potentially stuck orders, and scans per operator.

How: each dashboard reads directly from Supabase and reproduces the logic of the original Airtable views (filters, date windows, week boundaries), checked against the source so managers can trust the numbers.
