Records & Finance System

SK Records and Finance System

The Sangguniang Kabataan (youth council) of New Pandan, Matalam, Cotabato produces a steady stream of official documents: notices, agendas, minutes, resolutions, committee reports, activity designs, MOAs, and financial and accomplishment reports. Each one was typed by hand into Word, with the same names, dates, and numbers retyped across several files and a constant risk of mismatches.

What I built: a single-file web app that runs offline in Chrome or Edge with nothing to install. Officers enter a session once, and the app writes the Notice of Meeting, Order of Business, Committee Reports, Minutes, and every Resolution from that same data, as Word files that match the council's official letterhead, fonts, numbering, and line numbers exactly. It covers 11 document types in all, including Activity Designs, Memoranda of Agreement, Accomplishment, Documentation (photo), and Post-Activity Evaluation reports.

Finance and records: budget tables calculate line totals, totals, and remaining balances automatically. Monthly and quarterly financial report resolutions are written from just the date and the amount, with the amount spelled out in words, and ABYIP budget tables are supported. Evaluation reports compute weighted means and their verbal descriptions.

Built-in quality checks: before download, the app flags missing dates, duplicate numbers, incomplete years, and sessions without a quorum. A ✨ Write with ChatGPT button drafts formal WHEREAS and RESOLVED clauses using only the facts provided, with an API credit tracker and a copy-paste fallback for users without an API key. It also writes Facebook captions in the council's own style.

How it's engineered: a Python tool converts the council's real Word documents into fillable templates, and a JavaScript engine fills them. The whole app builds into one HTML file, and eight Playwright end-to-end test suites click through it in a real browser to keep each release working. Backups move all data, including photos, between computers.

11 document types Generated from one set of session data, matching the official formats exactly

AI App

Receiving Digitizer with AI Auto-Fill

Paperwork that came with received shipments (packing slips, BOLs, invoices, damage reports) was kept on paper, which made it slow to find later and easy to lose.

What I built: a phone-first web app. A receiver scans a QR code at the receiving door, photographs the paperwork, checks it's readable, and submits. Scans go to private cloud storage, the details go to a database, and a searchable archive lets the team find any document in seconds. Sign-in is role-based through Auth0.

The AI layer: in V2, Claude reads the captured pages and fills in the form fields automatically, flagging anything it couldn't read clearly. The receiver only types what's missing. If the AI is slow or unavailable, the app falls back to manual entry so receiving never stops.

How I shipped it safely: V2 runs as a separate preview deploy against clearly named test tables and storage, so new features get tested without touching live data.

Paper → searchable Every received document captured, stored, and findable from a phone

Live Production Tracking Dashboards

Production status lived in Airtable reports that were hard to read on the floor, and some were too big for Airtable to even display.

What I built: a suite of 69 live web dashboards covering every stage of production: cutting, sewing, foam, blowing, packing, inventory pulls, shipments between locations, custom orders, overdue and potentially stuck orders, and scans per operator.

How: each dashboard reads directly from Supabase and reproduces the logic of the original Airtable views (filters, date windows, week boundaries), checked against the source so managers can trust the numbers.
